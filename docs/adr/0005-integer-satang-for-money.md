# Represent money as integer satang

All persisted monetary values use a 32-bit PostgreSQL `INTEGER` count of satang across persistence and branded TypeScript `Satang` service contracts, with baht used only for presentation. A Wallet's four compartments together may hold at most `2_000_000_000` satang (฿20,000,000), leaving arithmetic headroom below the type maximum; pending inbound funds count toward that capacity, and an overflow fails closed without releasing its source reservation. PostgreSQL may widen an `INTEGER` sum while evaluating an aggregate query, but the schema defines no `BIGINT` money columns. KUQuest Wallets are THB-only, so financial rows do not repeat a constant currency column. A single unit preserves sub-baht values and exact arithmetic without floating-point, PostgreSQL `money`, JavaScript `bigint`, or the previous design's mixed-unit conversions and premature whole-baht rounding.
