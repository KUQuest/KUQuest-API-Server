# Keep money behavior behind application services

Money behavior lives in plain TypeScript application services rather than Elysia routes or PostgreSQL stored functions. PostgreSQL triggers may enforce cross-row integrity and immutability, but they do not choose workflow transitions or replace the services. Future HTTP adapters own authentication, validation, and status mapping; future Quest workflows pass their database transaction into balance-changing money services so Quest and ledger state commit atomically. Provider calls use staged transactions and never hold a database transaction open across the network. Only authenticated provider webhook ingress inherently remains HTTP-facing: it durably records an event and acknowledges it, while a separately invoked worker service claims and processes inbox rows with retries rather than relying on in-process fire-and-forget work.
