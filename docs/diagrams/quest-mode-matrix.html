4 Quadrant Mode × Participation Matrix

Complete interaction lifecycle sequence and API endpoint routing across all four combinations of Selection Modes (FIRST_COME_FIRST_SERVED, CANDIDATE) and Participation Shapes (SINGLE, GROUP).

Mode × Participation 2×2 Invariants

Dimension SINGLE (Headcount = 1) GROUP (Headcount = 2–20)
FIRST_COME_FIRST_SERVED Quadrant 1: Single direct join (POST .../join). Single starter, single submitter, 100% individual reward. Quadrant 3: Slot-by-slot direct join. Work chat opens on 1st join. Underfilled consensus. Every worker starts and submits. Partial completion allowed.
CANDIDATE Quadrant 2: Applications submitted (POST .../applications). Hirer selects 1 candidate, rejecting others. Single starter & submitter. Quadrant 4: Candidate Team with 24h Join Code. Leader-only start and submit. All-or-nothing team outcome. 100% worker reward pool paid exclusively to Leader.
QUADRANT 1

SINGLE × FIRST_COME_FIRST_SERVED

Instant assignment on first click. Headcount = 1. Fast, frictionless direct worker fulfillment.

Key Domain Rules

  • Headcount: Exactly 1 worker. First valid join wins slot immediately.
  • Auto-Cancel: If no worker joins before startTime, quest cancels and refund settles.
  • Start Work: Single worker must trigger start between startTime and dueAt.
  • Proof: Single proof submission draft sent before dueAt.

Primary Endpoints

  • POST /api/v2/quests/:id/publish: Publishes draft & reserves escrow.
  • POST /api/v2/quests/:id/join: Instant direct assignment.
  • POST .../proof-submissions/:id/submit: Worker submits proof.
  • POST .../proof-submissions/:id/review: Hirer approves or rejects.
  • POST /api/v2/quests/:id/reviews: 1 Hirer-Worker rating pair.
QUADRANT 2

SINGLE × CANDIDATE

Vetting flow. Candidates apply individually while open. Hirer reviews and selects exactly one applicant.

Key Domain Rules

  • Applications: Candidates can apply and withdraw while QUEST_OPEN.
  • Candidate Inquiry: 1-on-1 private chat available per applicant; closes upon assignment.
  • Atomic Rejection: Selecting one candidate immediately rejects all other applicants.
  • Unselected Expiration: If no candidate is selected by startTime, quest auto-cancels.

Primary Endpoints

  • POST /api/v2/quests/:id/applications: Candidate applies to quest.
  • POST .../applications/:id/withdraw: Candidate withdraws application.
  • POST .../applications/:id/select: Hirer selects chosen applicant.
  • POST .../proof-submissions/:id/review: Hirer review & settlement.
  • POST /api/v2/quests/:id/reviews: 1 Hirer-Worker rating pair.
QUADRANT 3

GROUP × FIRST_COME_FIRST_SERVED

Multi-slot direct join (2–20 workers). Work chat opens on 1st join. Underfilled consensus protocol at start time. Partial success permitted.

Key Domain Rules

  • Work Chat: Opens immediately upon 1st worker joining slot 1.
  • Underfilled Protocol: At startTime, Hirer has 10m to proceed/cancel; all workers have 10m to consent. Total pool splits equally among active workers.
  • Start Duty: EVERY active worker must start work independently.
  • Partial Success: One worker failing fails quest, but workers who completed work keep their reward!
  • Conduct Reports: Workers can file CONDUCT_NO_SHOW against inactive peers.

Primary Endpoints

  • POST /api/v2/quests/:id/join: Workers join slot-by-slot.
  • POST .../underfilled/decision: Hirer decides to proceed underfilled.
  • POST .../underfilled/consent: Workers consent to equal split.
  • POST .../proof-submissions/:id/submit: Each worker sends proof.
  • POST .../proof-submissions/:id/review: Per-worker Hirer decision.
QUADRANT 4

GROUP × CANDIDATE

Candidate Team formation. Team Leader controls roster via 24h Join Code. Leader-only start & submit. All-or-nothing team outcome; 100% payout to Leader.

Key Domain Rules

  • Team Formation: Leader sets headcount (2..published headcount) & sends 24h Join Code.
  • Submission Lock: Leader submits team with text + file; team cannot withdraw.
  • Leader-Only Duty: Team Leader is the SOLE required starter and proof submitter. Teammates have no individual submission duty.
  • All-or-Nothing Outcome: Proof approval completes EVERY teammate assignment; rejection fails all.
  • Reward Distribution: The entire worker reward pool for all published slots is disbursed ONLY to the Team Leader.

Primary Endpoints

  • POST /api/v2/quests/:id/teams: Leader creates forming team.
  • POST .../teams/:id/join-code: Regenerate 24h Join Code.
  • POST .../teams/:id/join: Teammates join with valid code.
  • POST .../teams/:id/submit: Leader submits immutable roster.
  • POST .../teams/:id/select: Hirer selects team & rejects others.
  • POST .../proof-submissions/:id/submit: Leader submits team proof.
