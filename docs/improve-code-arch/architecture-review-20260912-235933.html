problem
Three Admin reads re-derive the projection-versus-ledger balance check with identical SQL and the same four account-type literals, and Admin also re-derives the platform zero-sum check and the effective Money Policy interval, although Wallet owns and exports that knowledge.
solution
One narrow Wallet read for per-Wallet ledger balances plus the platform zero-sum total, reusing the existing derivation, and route the policy read through the exported resolver.

  • account vocabulary stops leaking
  • deep Wallet read, shallow Admin reads
  • subledger checks stop forking
